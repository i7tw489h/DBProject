# 数据库大作业 -DBProject

```
   校园 AI 食堂智能点餐与营养推荐系统
```

一、先记住：我们整个项目 = 3 大块
1.学生端（网页，手机 / 电脑都能用）
2.AI 智能模块（加分核心）
3.食堂管理端（后台）

二、超级详细・可直接分工的功能清单（逐字讲透）
（一）学生端功能（所有人都能懂、每天都用）

1. 用户模块（必做，对应作业：登录注册、密码加密）

注册：账号、密码、姓名、学院、手机号
登录：账号密码登录
个人信息：身高、体重、年龄、性别
饮食目标：减脂 / 增肌 / 正常 / 养胃
忌口设置：不吃辣、不吃香菜、清真、过敏、素食
密码用 MD5 加密 存数据库
解决问题：身份识别、个性化服务基础

1. 菜品浏览与查询（对应：CRUD、数据库查询）

按窗口查看：一楼、二楼、早餐窗口、面食窗口
按分类：荤菜、素菜、汤、主食、小吃
查看菜品详情：
o图片
o价格
o配料
o营养：热量、蛋白质、脂肪、碳水
收藏喜欢的菜品
解决问题：快速找想吃的、了解营养、避免踩雷

1. 在线点餐 + 下单（核心！对应：事务）

购物车：加菜、减菜、清空
提交订单
选择取餐时间段
模拟支付
生成取餐码
解决问题：不用排队、到店直接取餐

1. 订单管理（对应：CRUD、视图）

查看全部订单
查看待取餐、已完成、已取消
查看取餐码
取消未取餐订单
查看订单详情：买了啥、多少钱、营养合计
解决问题：订单可查、可追溯、不混乱

1. 个人营养中心（AI + 数据库亮点）

今日营养摄入统计：热量、蛋白、脂肪、碳水
历史饮食记录
营养分析：是否超标、是否不足
ECharts 图表展示：趋势图、饼图
解决问题：健康吃饭、可控热量、辅助减脂增肌

（二）AI 智能功能（老师最加分、创新分拉满）

1. AI 个性化推荐

根据你的历史订单猜你喜欢
根据忌口自动过滤不能吃的
根据目标推荐：
o减脂 → 低卡
o增肌 → 高蛋白
o养胃 → 清淡
解决问题：选择困难、不知道吃什么

1. AI 一键智能配餐

点一下按钮，系统直接给你配好一整餐：
减脂餐
增肌餐
低糖餐
养胃餐
清淡餐
解决问题：快速搭配、不用自己算营养

1. AI 饮食健康评价

“你今天热量超标”
“你蛋白质摄入不足”
“你最近油盐偏高，建议清淡”
解决问题：科学饮食、健康管理

1. AI 销量预测（给食堂用）

根据历史数据预测明天哪些菜好卖
帮助食堂少浪费、备餐更准
解决问题：食堂备餐盲目、浪费严重

（三）食堂管理员后台（对应：数据库管理、权限）

1. 菜品管理

新增菜品：名称、价格、图片、营养、配料、窗口
修改菜品信息
下架 / 上架菜品
设置库存
对应作业：CRUD、数据库约束

1. 订单管理

查看所有订单
接单、标记出餐
查看取餐码
按时间段、窗口筛选订单
对应作业：多表查询、视图

1. 库存与运营

下单自动扣库存（触发器）
库存不足提醒
菜品销量排行
销售额统计
热门菜品、学生偏好统计
对应作业：触发器、存储过程、数据可视化

三、这个项目到底解决什么问题？（你必须背下来）
1.学生排队太久 → 线上提前点，到店直接取
2.不知道吃什么 → AI 推荐、一键配餐
3.想吃健康但不会算 → 营养展示 + AI 分析
4.有忌口吃不安全 → 系统自动过滤
5.食堂备餐不准 → AI 预测销量、减少浪费

四、这些功能如何满足老师作业要求？（每条对应）

1. 数据库设计 25 分（全拿）

ER 图：用户、菜品、订单、订单明细、营养、日志
3NF：无冗余、无传递依赖
主键、外键、非空、唯一约束齐全
DDL 建库建表脚本完整
2. SQL 实现 20 分（全拿）
CRUD：全功能都用到
触发器：下单扣库存、记录日志
事务：下单流程原子性，要么全成功要么全回滚
视图：营养统计、销量排行
存储过程：批量更新、AI 推荐逻辑
3. 应用集成 15 分（全拿）
登录注册
密码 MD5 加密
Web 响应式界面（电脑 + 手机通用）
防 SQL 注入
稳定无 BUG
4. 技术创新 20 分（拿 19 分）
SpringBoot+Vue 主流框架
表单验证
分页
存储过程
Excel 导出
ECharts 图表
AI 智能推荐 + 营养分析
5. 实用性 15 分（全拿）
真正解决食堂痛点
界面简单好用
AI 功能不鸡肋
数据库支撑强
6. 文档 5 分（全拿）
需求、ER 图、SQL、说明、手册齐全
分工清晰
代码规范
